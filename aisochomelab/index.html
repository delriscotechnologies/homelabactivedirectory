AI-Assisted Security Homelab

Cristian Del Risco2026/10/26

This write-up records the configuration and test evidence from my homelab.

Project Topology

Two VMs form the monitoring setup. Windows 11 runs the Wazuh agent. Ubuntu hosts Wazuh Manager, Indexer and Dashboard, Hermes Agent, Ollama and the MCP server running in Docker.

Both VMs share a private network. The agent connects to the Ubuntu IP address. By default, it sends events over 1514/TCP and enrolls over 1515/TCP. The Dashboard provides browser access to the alerts.

Wazuh Deployment

Installation has two parts: the central services on Ubuntu and the agent on Windows 11. The following steps summarize a reproducible installation path; the screenshots show the observed results.

Ubuntu · Central Components

For a new installation, the assistant uses -a to set up Manager, Indexer and Dashboard on the same machine.

Ubuntu · bash
mkdir -p ~/homelab/wazuh
cd ~/homelab/wazuh
curl -sO https://packages.wazuh.com/4.14/wazuh-install.sh
sudo bash ./wazuh-install.sh -a

When installation finishes, the assistant displays the Dashboard credentials. Open https://UBUNTU_IP to sign in.

Windows 11

The Windows 11 agent was deployed from the Wazuh Dashboard. Under Agents management → Summary, select Deploy new agent. Choose Windows, enter the Ubuntu manager address and specify the agent name.

Run the generated installation command in PowerShell as administrator on Windows 11, then follow the service startup instructions shown in the Dashboard. Return to the agent list and confirm that the endpoint appears as Active.

Telemetry and Detection

One of the reasons I like Wazuh is the visibility it gives me into endpoint activity. I can review agent events, configuration assessments and file changes in one place. The screenshots below show how that telemetry appears in the dashboards.

The manager can also collect local Ubuntu logs and appears as 000. It does not require another agent on the same server, but the sources to monitor still need to be configured.

File Integrity Monitoring

On Ubuntu, FIM was configured to monitor /home/kali/Downloads continuously. The following entry belongs inside the existing <syscheck> block in /var/ossec/etc/ossec.conf:

Ubuntu · XML
<directories check_all="yes" realtime="yes">/home/kali/Downloads</directories>

On Linux, real-time FIM uses inotify to detect directory changes. The configured integration can then look up a file hash, and a positive result can trigger the response rule.

VirusTotal Integration and Active Response

I added VirusTotal to give file-integrity events more context. A new or modified file is worth investigating, but its reputation helps me decide what to do next. I also wanted to test whether Wazuh could use a positive result to trigger an automated response.

This is an example of the configuration I used, following the Wazuh documentation. The block goes inside <ossec_config> in the Ubuntu manager’s /var/ossec/etc/ossec.conf:

Ubuntu · XML
<integration>
  <name>virustotal</name>
  <api_key>API_KEY</api_key> <!-- Replace with your VirusTotal API key -->
  <group>syscheck</group>
  <alert_format>json</alert_format>
</integration>

This enables VirusTotal lookups for FIM alerts in the syscheck group. The integration queries file reputation by hash; it does not upload the monitored files.

The reported response commands are remove-threat-linux and remove-threat-win, associated with rule 87105 for a malicious VirusTotal result. The handlers use Python on Ubuntu and PowerShell on Windows 11.

Wazuh Active Response is rule-based. VirusTotal supplies reputation data and the configured handler performs the file operation; Hermes is not required to trigger this chain.

After editing the manager configuration, the changes were applied by restarting the service:

Ubuntu · bash
sudo systemctl restart wazuh-manager

Configuration Test

The initial EICAR test command used the path below. Later dashboard captures show test files under /home/kali/Downloads, the monitored directory configured above. Repeat tests must target a directory covered by FIM.

Ubuntu · bash · Initial test command
sudo curl -Lo /media/user/software/suspicious-file.exe https://secure.eicar.org/eicar.com

Automatic file removal was reported during the Ubuntu test. The dashboards show file events and VirusTotal results; attributing deletion to a specific handler requires its execution log. EICAR is a benign antivirus test file.

Vulnerability Detection

I enabled Vulnerability Detection because I also wanted to see which installed packages and applications might need patching. It complements event monitoring by comparing the inventory collected by Syscollector with known vulnerabilities from Wazuh’s Cyber Threat Intelligence platform.

I updated the manager configuration and restarted the service. This is the Wazuh 4.14 configuration reference for the module in /var/ossec/etc/ossec.conf:

Ubuntu · XML · Configuration reference
<vulnerability-detection>
  <enabled>yes</enabled>
  <index-status>yes</index-status>
  <feed-update-interval>60m</feed-update-interval>
</vulnerability-detection>

CIS Configuration Assessment

Wazuh’s Security Configuration Assessment is another feature I like because it turns system hardening into checks I can review. The CIS Benchmarks from the Center for Internet Security give me a baseline for settings such as password policies, account lockout and account security.

The Windows 11 assessment uses CIS Microsoft Windows 11 Enterprise Benchmark v3.0.0. This scan shows 131 passed, 343 failed and 8 not applicable checks, with a displayed score of 27%.

I use these results to prioritize configuration changes: review a failed check, understand its recommendation, apply the change where appropriate, and compare the next assessment. The score describes this benchmark assessment; it is not a count of exploitable vulnerabilities.

Discord Integration

I connected Hermes Agent to Discord so I can request investigation summaries and interact with the analyst from a messaging app, without keeping the Wazuh Dashboard open.

In this example, I asked Hermes for a daily SOC rundown. It replied with a SOC Daily SITREP covering incident management, monitoring, network discovery and action items. This gives me a convenient place to review its findings and follow up on the investigation.

The response also reports a permission issue affecting log extraction. I treat the summary as an investigation aid and check its claims against the underlying Wazuh events and tool results.

AI Investigation

Ollama Installation

Ollama was installed on Ubuntu before Hermes Agent to serve as its model provider. The setup was run from ~/homelab/ollama using the official Linux installer:

Ubuntu · bash
mkdir -p ~/homelab/ollama
cd ~/homelab/ollama
curl -fsSL https://ollama.com/install.sh | sh

I set up two models through Ollama: gemma4:31b-cloud in the cloud and qwen3.5:4b locally as the backup. The local model was slow on my computer, so I chose the cloud model for regular use through Ollama’s free cloud allowance. The local model is downloaded to the machine; cloud inference runs remotely.

Hermes Agent and Model Configuration

After installing Ollama, I configured Hermes Agent to use Ollama as its model provider and selected the cloud model as the primary model. This made the investigation workflow more responsive while keeping the local model available as a backup.

MCP Server Deployment

The MCP server was deployed with Docker Compose on Ubuntu, using ~/homelab/wazuh-mcp as the project directory. The service is available on port 3000.

The reported deployment check returned {"status":"healthy"} at http://localhost:3000/health. The service can be checked from Ubuntu with:

Ubuntu · bash
curl -s http://localhost:3000/health

The container uses host.docker.internal to reach the Wazuh server API on Ubuntu over HTTPS, port 55000. The API credentials are configured for this connection.

API Authentication

I keep the Wazuh API username and password in a .env file and pass them to the MCP container through Docker Compose. This keeps the credentials out of the application code.

The MCP server authenticates to POST /security/user/authenticate using the Wazuh API username and password. Wazuh returns a JSON Web Token (JWT), which is sent in the Authorization: Bearer header for subsequent API requests. The VirusTotal API key is a separate credential.

MCP Tool Interface

MCP gives Hermes a tool interface for Wazuh. Hermes discovers the available tools through tools/list and invokes a tool with structured arguments through tools/call. The MCP server translates that request into the relevant Wazuh API operation and returns the result for Hermes to interpret.

The Wazuh server API supports agent and manager operations. Searching stored alerts uses the Indexer or another alert source exposed by the MCP implementation. This lets Hermes combine system context with alert evidence during an investigation.

Notion Incident Tracking

I added Notion because I wanted tickets, investigation notes and response records in one organized workspace. The CyberOps Command Center keeps the work associated with an alert together, so I can follow an incident beyond what appears in the Wazuh Dashboard.

Sentinel Forwarding Layer

Sentinel is the custom Python process for continuous forwarding. It watches Wazuh’s JSON alert output at /var/ossec/logs/alerts/alerts.json, selects alerts with rule.level >= 10 and submits records through the Notion API.

I want each ticket to retain its source alert, endpoint, severity and response notes. Notion holds the working case record; the original technical logs remain in Wazuh. Access to the workspace and integration credentials needs to be restricted.

Final Thoughts

I configured Wazuh for endpoint monitoring, file-integrity checks, vulnerability detection and automated response, then connected Hermes through MCP for investigation. Working on both parts helped me understand the difference between the detection and response logic I configure and the analysis an AI agent produces.

What I liked most about Wazuh was the range of visibility available in one platform. Alongside SIEM event analysis, I could review software vulnerabilities, monitor file changes and assess Windows settings against CIS Benchmarks. The vulnerability assessment features connect with the work I associate with Qualys, while the configuration checks provide another perspective on endpoint security.

The integrations involved API authentication, credentials, container networking and service configuration. The MCP server runs in Docker Compose, Sentinel forwards selected alerts to Notion, and Discord provides an interface for requesting reports from Hermes. The local model was slow, so I used Ollama’s cloud model and kept the local model as a backup.

Before involving Hermes, I had to configure the rules, scripts and automations that make the response workflow function. For example, file removal follows a defined sequence: FIM detects a change, VirusTotal returns reputation data, and a matching Wazuh rule triggers the configured script. Hermes does not decide whether that rule-based deletion happens. The engineering behind those controls remains necessary.

The tools I would choose for a company depend on its systems, risks and operating needs. Here, I wanted to interact with Hermes, query the Wazuh environment and use the administrative tools exposed through MCP. Its investigation responses depend on the alerts, tool results and playbook instructions it receives. This supports context-aware analysis, incident summaries and suggested remediation steps that can be checked against the source events and tool calls.

With sufficient context and defined playbooks, AI agents can automate parts of initial triage and investigation documentation. They still need human judgment when decisions depend on business impact, asset criticality or context the agent does not have. For me, this changes what an entry-level analyst needs to demonstrate: understanding the underlying systems, checking the agent’s work and knowing when to challenge its recommendation. Familiarity with these integrations complements the security fundamentals needed to make those decisions.
